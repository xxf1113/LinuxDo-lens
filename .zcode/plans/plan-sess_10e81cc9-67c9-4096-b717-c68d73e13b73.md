# AI 总结全量抓取评论方案

**改动文件**：`LinuxDo 增强阅读集成AI.user.js`（单文件）

## 1. 主 IIFE：新增 `fetchAllTopicPosts(topicId, onProgress)` 工具函数

放在嵌套树 API 封装区（`fetchNestedTree` 附近，约 line 466 后）：

- `fetchJSON(${BASE}/t/${topicId}.json)` 获取 `post_stream.stream`（全部帖子 ID 列表）和 `title`；该响应自带的 ~20 条帖子直接放入 `Map(postId → post)`
- 剩余 ID 按 `PAGE_SIZE`(=20) 分批请求 `/t/${topicId}/posts.json?post_ids[]=...`（复用现有 `fetchPosts` 模式）
- 每批完成调用 `onProgress(doneBatches, totalBatches)` 供 UI 显示进度
- 最终按 `post_number` 排序，返回 `{ title, posts }`

## 2. `openModal` 的 ctx 上挂载该能力

在 ctx 定义处（line 1844-1852）增加：
`ctx.fetchAllTopicPosts = (onProgress) => fetchAllTopicPosts(topicId, onProgress)`

（不依赖 `ctx.postMap`——锚点跳转路径下 postMap 并未完整填充，独立拉取更可靠）

## 3. AI IIFE 改造

- 新增 `htmlToText(html)`：临时 DOM 解析 `cooked`，`<img>` 替换为 `[图片]` 占位，返回纯文本
- 新增 `buildTopicContent(ctx, onProgress)`：
  - 调 `ctx.fetchAllTopicPosts(onProgress)` 拿全量帖子
  - 跳过已删除帖（`!username || !cooked || deleted_at`）
  - `post_number === 1` → 主贴；其余 → `#N @username：内容` 格式
  - 防溢出保护：单条评论超 1000 字截断；评论总内容超 15 万字符时停止追加并注明"（内容过长，已省略后 X 条评论）"
  - 输出格式与现有 `getModalContent` 完全一致（标题 / 【主贴内容】/【评论区内容】共 N 条），保证提示词兼容
- `doSummarize` 改为 async：
  - 优先走 API 全量抓取，AI 面板显示"正在获取全部评论（x/y 批）..."进度
  - 抓取失败或 ctx 无此能力时，回退到现有 `getModalContent`（DOM 抓取）并在控制台告警
  - 后续 `summarizeTopic` 调用流程不变
